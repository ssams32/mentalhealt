# 06. Mock API 및 통합 테스트 계획

- 설계 기준: `origin/main 34c28d8` (브랜치 `external-api-engine`)
- 근거: 2단계 설계 문서 3번 (보안·설정·운영) + 의뢰서 5단계 테스트 목록
- 상태: **설계 단계. 코드 변경 없음.** 실제 홈페이지 연결 전에 Mock API로만 테스트한다.
- 표기: **[설계]**는 이번 단계에서 정한 것, **[미확정]**은 홈페이지 API 명세가 없어 정할 수 없는 것.

---

## 1. Mock 구성 원칙

- Mock 서버는 `server/external-api/mockHomepageApi.js`로 새로 만든다.
  선례는 `server/survey/mockTrackAApi.js`(인메모리 합성 Mock)다.
- Mock은 `HOMEPAGE_API_MODE=mock`일 때만 동작한다.
  production/staging에서는 Mock이 절대 뜨지 않는다 (모드 가드).
- Mock 데이터는 전부 합성 데이터이며, 이름·전화는 `SYNTHETIC 테스트사용자`,
  `010-0000-0000`처럼 눈에 띄게 표시한다 (survey 스테이징 규칙과 동일).
- **실제 운영 개인정보는 테스트에 사용하지 않는다.**
- 실제 홈페이지 API에는 접속하지 않는다 (명세가 없어 Mock만 사용).
- 실제 NAS 라이브 데이터는 사용하지 않는다 (로컬 worktree + mock DATA_DIR만 사용).

---

## 2. 테스트 계획표

의뢰서 5단계의 13개 테스트 항목과 2단계 설계의 T1~T10을 하나로 맞췄다.

| # | 테스트 (의뢰서 5단계) | Mock 구성 | 확인 방법 | 합격 기준 |
|---|---|---|---|---|
| T1 | 정상 인증 | Mock이 유효 키(`mock-homepage-key`)로 200 + 의뢰 2건·척도 1건을 반환 | 수동 동기화 실행 → 상태 `SUCCESS`, 저장 건수 확인 | 200 응답, 건수가 이력에 기록됨, 키가 로그·응답에 없음 |
| T2 | 잘못된 인증키 | Mock이 잘못된 키에 401 반환 (키를 `wrong-key`로 바꿔 실행 — Mock 모드에서만 허용) | 수동 동기화 실행 → 상태 `FAILED`, 에러 코드 `HOMEPAGE_AUTH_FAILED` | 401을 받고, 실패 큐에 `errorCode=HOMEPAGE_AUTH_FAILED`로 기록되며, 자동 재시도를 하지 않음 (401은 재시도 불가). 키 본문이 로그에 없음 |
| T3 | 신규 의뢰 수신 | Mock이 의뢰 3건 반환 (필수 필드 완비 2건, 필수 필드 부족 1건) | 폴링 1주기 실행 → `PendingReferrals` 저장 확인 | 완비 2건 저장, 부족 1건은 실패 큐 또는 검토 큐에 `VALIDATION_FAILED`로 기록. 저장 전 ack를 보내지 않음을 코드 경로로 확인 (`await persistData` 이후에만 ack) |
| T4 | 신규 척도검사 수신 | Mock이 척도검사 2건 반환 (PHQ-9 1건, GAD-7 1건 — 기존 척도 코드 사용) | 폴링 1주기 실행 → `SurveySubmissions` 저장 확인 | 2건 저장, `scale`·총점·`sourceSubmissionId` 연결 고리 확인. 신규 척도 코드(미확정 목록 외)가 와도 저장 구조가 깨지지 않음 |
| T5 | 중복 접수 | Mock이 T3과 동일한 고유 접수 ID 3건을 다시 반환 | 두 번째 폴링 실행 → 저장 건수·이력 확인 | 두 번째 폴링에서 3건 전부 스킵 (`skipped=3`, `stored=0`). `Referrals`·`PendingReferrals`에 중복 행이 생기지 않음. seen-set에 ID가 남아 있음 |
| T6 | 필수 필드 누락 + 잘못된 데이터 형식 | Mock이 필드 누락·형식 오류·초과 길이·허용 문자 밖 ID를 섞어 반환 | 폴링 1주기 실행 → 실패 큐 확인 | 오염된 건만 실패 큐에 들어가고, 정상 건은 저장됨 (한 건의 오염이 전체 폴링을 막지 않음). 실패 사유가 에러 코드로 기록됨 |
| T7 | 암호화 및 복호화 | (a) Mock baseUrl을 `http://`로 바꿔 production 모드 기동 시도 → 거부되는지 확인. (b) 키·개인정보가 로그·응답·설정 JSON에 없는지 grep으로 확인. (c) 홈페이지 페이로드 자체의 암호화 여부는 **[미확정]** — 업체 명세에 따라 별도 테스트를 추가한다 | (a) 기동 로그·상태 확인. (b) `grep -r "mock-homepage-key" DATA_DIR/ logs/`, 설정 JSON에 키 필드가 없는지 확인 | (a) http URL이 production 모드에서 거부됨. (b) 키 본문이 디스크·로그 어디에도 없음. (c)는 명세 확정 후 추가 |
| T8 | 통신 오류 및 재시도 (네트워크 단절 포함) | Mock 서버를 끄거나 타임아웃(1ms)을 설정해 연결 실패 유발 | 폴링 실행 → 실패 큐·재시도 기록 확인 | 연결 실패가 실패 큐에 `errorCode=TIMEOUT` 또는 `NETWORK_ERROR`로 기록되고, 지수 백오프 간격(1000ms→2000ms→4000ms, 최대 60000ms)으로 재시도됨. 3회 실패 후 `FAILED_PERMANENT`로 전환 |
| T9 | 저장 실패 | Mock이 정상 응답을 주되, 저장 단계에서 `persistData`를 실패하게 만든다 (테스트용 주입) | 폴링 실행 → 재시도 큐 확인 | 저장 실패 건이 재시도 큐에 `PERSIST_FAILED`로 기록되고, ack를 보내지 않음 (저장 전 ack 금지 확인). 다음 사이클에서 재처리됨 |
| T10 | 재시도 및 복구 | T8의 실패 상태에서 Mock 서버를 다시 켠다 | 다음 폴링 주기 실행 → 저장·이력 확인 | 실패했던 항목이 다음 주기에 다시 가져와져 저장됨. seen-set·이력이 정상 갱신됨 |
| T11 | 중복 파이프라인 충돌 | 스크레이퍼를 ON으로 켠 상태에서 엔진을 실행한다 | 엔진 실행 시도 → 상태 확인 | 엔진이 `SCRAPER_CONFLICT`로 실행을 거부하고, 이중 수집이 일어나지 않음. 감사 이벤트 1건 기록 |
| T12 | 기존 의뢰관리 기능 영향 여부 | Mock 모드로 엔진을 켠 채 기존 기능 스모크 테스트: 의뢰 목록 조회·의뢰 생성·설문 가져오기 상태 조회·백업 설정 조회·홈페이지 의뢰 요약 조회 | 각 API 호출 → 응답 확인. `npx tsc --noEmit -p tsconfig.json` 실행 | 기존 API가 전부 정상 응답. 타입검사에서 신규 오류 0건 (기존 오류 16건은 기준선으로 유지 — 1단계 분석 기준과 동일). 엔진 마운트 전후로 기존 라우트 목록이 바뀌지 않음 |
| T13 | 인증정보 GitHub 노출 여부 | Mock 키로 개발한 뒤, 커밋 전 스테이징된 diff를 검사 | (1) `git diff --cached`에서 `HOMEPAGE_API_KEY` 값·키 본문 패턴 grep. (2) `.gitignore`에 `.env`·`secrets/` 포함 확인. (3) `.dockerignore`에 `.env*` 포함 확인. (4) `EngineSettings.json`에 키 필드가 없는지 확인. (5) `git log --all -p`에서 키 패턴 grep (이력 포함 검사) | 키 본문이 diff·이력·이미지·설정 JSON 어디에도 없음. 검사 스크립트(`scripts/check-env-example.mjs`와 같은 절차, 04 문서 §8-2 참조)가 통과함 |

## 3. 테스트 실행 순서

1. **T12(기존 기능)를 먼저 실행해 기준선을 잡는다** (엔진 OFF 상태).
2. 엔진을 mock 모드로 켜고 T1→T6을 순서대로 실행한다.
3. T7·T8·T9·T10·T11·T13을 실행한다 (보안·복원력·충돌·노출 검사).
4. **T12를 다시 실행해 기준선과 비교한다** (회귀 확인).
5. 결과를 테스트 결과 보고서로 정리한다 (테스트별 합격/불합격·증거·미확정 항목).

---

## 4. 합격 기준 (전체)

- T1~T13이 전부 합격 기준을 만족한다.
- 기존 기능(T12)이 엔진 ON/OFF 양쪽에서 정상 동작한다.
- 타입검사에서 신규 오류 0건 (기존 오류 16건은 기준선).
- 키 본문이 디스크·로그·diff·이력·이미지·설정 JSON 어디에도 없다.
- 저장 전 ack 금지 (`await persistData` 이후에만 ack)가 코드 경로로 확인된다.
- 테스트 데이터는 전부 합성 데이터이며, 실제 운영 개인정보를 사용하지 않는다.

---

## 5. 테스트에서 쓰지 않는 것

- 실제 운영 개인정보 (합성 데이터만 사용).
- 실제 홈페이지 API (명세가 없어 Mock만 사용).
- 실제 NAS 라이브 데이터 (로컬 worktree + mock DATA_DIR만 사용).
